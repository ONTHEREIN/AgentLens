## 1. 复现方式

```bash
cd 传智杯/agentlens
pip install -r requirements.txt

python -m agentlens validate cases/     # 5 条用例全部通过校验
python -m agentlens run cases/ --trace  # 批量执行 + 打印每条完整 span 链路
python -m agentlens run cases/ --repeat 3   # 复跑一致性
python -m agentlens run cases/ --strict     # CI 门禁语义：有失败 -> 退出码 1
```

全流程零网络、零 LLM 调用、零外部数据依赖。产物落 `results/<run_id>/traces.jsonl`（唯一真相源）+ `summary.json`。

## 6. 这一轮证明了什么 / 没证明什么

**已证明**

1. `plan / tool_call / observation / retrieve / generate / guardrail` 六类 span **足以支撑归因** —— 两种失败被稳定判到 L2 与 L6，且能指出证据 span
2. schema 是**强约束**的（pydantic `extra=forbid`）：schema 一漂移，写入前就炸，不会等到归因阶段才发现信息缺失
3. 用例非法时 **fail fast 且报行号**（实测：`cases/interpret_001.yaml:21 字段 expect.note 非法`）
4. `--repeat 3` 三次结果完全一致（60.0% / L2×3 / L6×3）→ 复现性基线成立
5. `--strict` 可作 CI 门禁（有失败退出码 1），M4 的 gate 语义已提前打通

**没证明（不许在材料里夸大）**

1. **归因准确率未知**：v0 决策树只在 5 条构造用例上跑通，未经 100 条人工标注校准（M2 才出数）
2. **无 LLM 裁判**：纯规则，答案忠实度类维度尚未覆盖
3. **用例量不足**：5 条 vs 目标 300 条，自动生成占比 0%
4. trace 里 `耗时 0.0ms` 是真实墙钟（本地规则实现，微秒级），接入真 LLM 后才有性能意义
5. 单一被测对象，G5「接入新 Agent ≤2 人时」尚未验证
