# 复现指南：从零复跑出同样的结论

**不需要联网，也不需要任何 API key**：被测智能体的每一步大模型回复都录在 `recordings/` 里，
回放时工具照常执行，大模型按录制返回；LLM 裁判的结论按内容哈希缓存在 `judgements/` 里。
2026-11-10 在干净环境（全新 clone、只装最小依赖、无 `.env` 文件）验证过：354 条用例的判定与归因层与提交结果逐条一致。

## 1. 准备（约 2 分钟）

需要 Python 3.10+（AgentLens）与 3.11+（被测智能体），推荐用 [uv](https://docs.astral.sh/uv/)。
两个目录必须**并排放**（AgentLens 默认在同级目录找被测智能体，也可用环境变量 `ONEGZUS_API_DIR` 指定）：

```
任意目录/
├─ AgentLens/
└─ GZUS-PRO-agent/        # 被测智能体，feat/agent 分支
```

```bash
# AgentLens：依赖只有 pydantic / pyyaml / rich
cd AgentLens
uv venv -p 3.10 .venv && uv pip install -p .venv/bin/python -r requirements.txt

# 被测智能体：回放只需要 pydantic（不需要 web 框架，也不需要大模型 SDK）
cd ../GZUS-PRO-agent/services/api
uv venv -p 3.11 .venv && uv pip install -p .venv/bin/python pydantic
cd ../../../AgentLens
```

不用 uv 时，`python3 -m venv .venv && .venv/bin/pip install ...` 等价。

## 2. 三条命令复现主结论

```bash
.venv/bin/python -m agentlens run cases/onegzus/   --adapter onegzus --llm-judge --html
.venv/bin/python -m agentlens run cases/generated/ --adapter onegzus --llm-judge --html
.venv/bin/python -m agentlens run cases/faults/    --adapter onegzus --llm-judge --html
```

期望输出（末尾汇总行）：

| 用例集 | 内容 | 期望 |
|---|---|---|
| `cases/onegzus/` | 人工黄金用例 69 条 | `可靠性分 84.1 / 100    通过 58 · 失败 11` |
| `cases/generated/` | LLM 改写用例 272 条 | `可靠性分 77.6 / 100    通过 211 · 失败 61` |
| `cases/faults/` | 数据面故障注入 13 条 | `可靠性分 61.5 / 100    通过 8 · 失败 5` |

每次运行落盘到 `results/<run_id>/`：`traces.jsonl`（唯一真相源）、`summary.json`、`report.html`。

## 3. 复现归因器校准

```bash
.venv/bin/python -m agentlens run cases/calibration/ --adapter onegzus --llm-judge
```

期望「故障注入校准」表末行：`合计  159/159 = 100.0%  …  158/159 = 99.4%`（检出率 / 归因准确率）。

## 4. 不依赖被测智能体的自检

```bash
.venv/bin/python -m agentlens validate cases/onegzus/   # 只校验用例：通过 69 条用例
.venv/bin/python -m agentlens run cases/                # 内置桩对象 5 条种子：3 PASS / 2 FAIL，可靠性分 60.0
```

## 5. 看单条缺陷的完整链路

```bash
# 例：D-008「大一上」无依据推断学年
.venv/bin/python -m agentlens run cases/onegzus/param_freshman_term_001.yaml --adapter onegzus --llm-judge --trace
```

`--trace` 会打印完整的 span 树（规划 → 工具调用 → 观测 → 生成）、逐项判定表和归因面板。
其余缺陷的用例名见 `02-缺陷清单/缺陷清单.md`。

## 6. 审计台（可选）

```bash
.venv/bin/python web_demo/server.py    # → http://127.0.0.1:8765，仅绑本机回环地址
```

读取 `results/` 下的运行结果；页面上发起的运行同样只走回放，不调用大模型。

## 7. 门禁（可选）

```bash
.venv/bin/python -m agentlens compare <基线 run_id> <本次 run_id>
```

新增失败或 p90 耗时涨超 20% 时退出码为 1。拿同一份录制跑两次做对比，结论应为「无变化」。

## 8. 重新录制（需要联网和 API key，评审不必做）

仅在想用真实大模型重新生成结论时需要：

- 被测智能体的模型配置写在 `GZUS-PRO-agent/services/api/.env.agent`（`AGENT_LLM_BASE_URL / API_KEY / MODEL`），
  并 `uv pip install openai`。
- LLM 裁判与用例生成的模型配置写在 `AgentLens/.env.judge`（`AGENTLENS_JUDGE_BASE_URL / API_KEY / MODEL`）。

```bash
AGENTLENS_RECORD=1 .venv/bin/python -m agentlens run cases/onegzus/ --adapter onegzus   # 覆盖录制
.venv/bin/python -m agentlens generate cases/onegzus/                                  # 生成改写用例
```

大模型输出有随机性，重新录制后的具体失败条目会有出入；**提交的结论以仓库里的录制为准**。

## 常见问题

- **用例全部「跳过」，`--trace` 里提示「找不到软帮手环境」**：两个目录没有并排，或被测智能体的 `.venv` 没建；
  用 `ONEGZUS_API_DIR=/path/to/GZUS-PRO-agent/services/api` 指定。
- **通过 / 失败条数与上表不同**：多半是裁判缓存未命中（用例或录制被改过）。没有配置裁判模型时，
  这些条目的 LLM 忠实度不判、只标记降级、不算失败，所以失败数会变少；恢复原文件即可。
