## 1. 两条参赛路径（任选其一）

### 路径一：智能体应用的全方位测试（侧重测试方案设计与执行）

先基于智能体开发框架（**Dify、Coze、LangChain** 等）搭建一个面向具体场景的 AI 智能体应用
（官方建议场景：**校园智能助手**、法律文书辅助、健康咨询顾问、代码辅助工具、智能客服），
然后针对该智能体设计并执行系统性测试。

需提交：智能体应用介绍、完整的测试方案文档、测试用例集、测试执行记录、缺陷分析报告。

### 路径二：智能体测试工具开发（侧重工具创新）

开发专门针对 AI 智能体的测试辅助工具或平台，官方给的四个例子：

| 官方例子 | 与我们的关系 |
|---|---|
| 智能体自动化测试框架：批量回归测试、结果自动判定 | 对应 `runner/` + `--repeat` 一致性 |
| RAG 知识库测试工具：检测冲突/冗余/错误，评估检索质量 | 部分对应 `retrieval_quality` 维度 |
| 对抗性用例自动生成器：用大模型生成越狱提示词、边界用例 | 对应变异生成器（需补对抗性方向） |
| **智能体行为可视化与审计平台：记录并可视化"思考-行动"链路，辅助缺陷定位** | **就是 AgentLens 本体** |

需提交：可运行的工具原型、技术方案说明、实际应用效果验证。

## 2. 七个测试维度（官方原文，出现在路径一中）

> 「测试维度包括但不限于：」

| # | 官方维度名 | 官方描述 |
|---|---|---|
| 1 | 功能准确性测试 | 验证智能体在典型场景下是否能给出正确、有用的回答 |
| 2 | 工具调用测试 | 验证智能体能否在正确时机调用正确的工具/API，并正确处理工具返回结果 |
| 3 | RAG 检索质量测试 | 验证智能体在检索知识库时的召回准确率与回答忠实度 |
| 4 | 多轮对话测试 | 验证智能体在多轮交互中的上下文记忆能力与逻辑连贯性 |
| 5 | 对抗性与安全测试 | 设计越狱提示词、角色扮演诱导等攻击手段，检验智能体的安全护栏是否牢固 |
| 6 | 边界与异常测试 | 测试智能体在输入不完整、超长上下文、工具异常返回等边缘场景下的表现 |
| 7 | 性能测试 | 评估智能体在并发请求下的响应速度与资源消耗 |

**注意**：「包括但不限于」→ 允许超出，但七个是基准盘。前文还有一句点题：

> 传统的接口测试、页面功能测试已难以覆盖智能体的"思维链路"，测试人员需要理解智能体的决策逻辑，设计针对性的验证策略。

## 10. 定位决策：主线走路径二，用路径一的产出做效果验证

**为什么主线是路径二（工具开发）**

路径一硬性要求「基于 Dify / Coze / LangChain 搭建」智能体应用。我们的被测对象是自研 Python agent
（复刻软帮手真实契约），不基于这些框架，走路径一会在第一条要求上被诟病。
路径二要求「可运行的工具原型 + 技术方案说明 + **实际应用效果验证**」——AgentLens 正好是原型，
软帮手 agent 正好是"实际应用效果验证"的被测对象。

**为什么还要把路径一吃满**

路径一的五份交付物（应用介绍、测试方案文档、测试用例集、测试执行记录、缺陷分析报告）
和路径二的"实际应用效果验证"是同一批东西。做一份工作，同时覆盖：

- 路径二的**创新性 20%**（工具创新）
- 路径一的**智能体理解与测试深度 30%**（七维度全覆盖）
- 路径一的**完整性 10%**（端到端可执行、可验证结论）

**一句话定位**

> AgentLens 是路径二「智能体行为可视化与审计平台」的一个具体实现：
> 它先把智能体的"思考-行动"链路录成结构化 trace，再逐 span 判定、归到六类根因，
> 最后交出缺陷清单。软帮手（OneGZUS）作为真实被测对象，提供"实际应用效果验证"。

## 11. 六个评分维度的现状与缺口

| 权重 | 维度 | 我们现在 | 判断 |
|---|---|---|---|
| 30% | 智能体理解与测试深度 | 六类 span + 七维度 + L0–L6 归因；覆盖"规划/工具调用/RAG" | **良好**，但"记忆"一环缺（见下） |
| 25% | AI 能力应用水平 | 有提示词设计、用例自动生成；但判定刻意不用 LLM | **有失分风险**（见下） |
| 20% | 创新性 | span 级 oracle，把"对错"降解为可判定子问题 | **强项** |
| 10% | 完整性 | record/replay + 一条命令出报告 | **强项** |
| 10% | 实用性与商业价值 | 被测对象是真实上线产品 OneGZUS | **强项** |
| 5% | 社会价值 | 有 L6 护栏误伤，但缺对抗性攻击面 | **偏弱**（见下） |

### 三个必须补的缺口

**缺口一：记忆（占 30% 的权重里被明确点名）**
官方原文写「智能体架构（**规划、记忆、工具调用、RAG**）」——"记忆"是四个核心能力之一。
我们只有 `plan / tool_call / observation / retrieve / generate / guardrail` 六类 span，
**没有记忆 span，`Trace` 也没有轮次结构**。多轮对话维度无处安放。
→ 需加 `MemorySpan`（读/写/遗忘）+ `Trace.conversation_id` + `Trace.turn`。

**缺口二：AI 自动判定（占 25%）**
官方原文写「AI 自动判定测试结果」「自动化判定」「Prompt Engineering 质量」。
我们原设计"六类断言全部不依赖 LLM 裁判"——这在"AI 能力应用 25%"上是**主动放弃分数**。
→ 改为**双轨判定**：确定性 span 断言做主判（可复现、可解释），LLM 裁判做语义判定（答案忠实度、
多轮连贯性、护栏是否过度拒答），并用 Cohen's Kappa 证明裁判与人工一致。两条轨都要在文档里讲清楚。

**缺口三：对抗性（占 5% 社会价值 + 30% 的"特有风险点"）**
官方原文写「设计越狱提示词、角色扮演诱导等攻击手段」。我们现在只有"敏感词误拒"一条 L6 样本。
→ 需补一类攻击用例：越狱（"忽略之前所有指令"）、角色扮演诱导（"假装你是管理员"）、
间接注入（工具返回内容里藏指令）、超长上下文淹没。
